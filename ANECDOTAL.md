## Personal Anecdote

I came directly from C# to learn C++. Since they both use C style I don't think it was bad overall. C# is Microsoft's Java, and it's just as bad when it comes to performance, memory management, design, and hypnotized OOP devs. This was back with .NET 4.7 and I naturally went to MSVC because it was bundled with Visual Studio Community (I'm sure it is still widely used) on Windows. My opinion is that a super beginner should use Visual Studio Community if they are on Windows because it will definitely help you create your first program within an hour of time invested. The faster you are comfortable straying away from a particular IDE the better. All developers must understand the command line/terminal at one point. There are multiple reasons for this, I for one don't like managing dependencies or projects within the IDE because it is not portable or future proof. The GUI debugger is excellent for a beginner and so is setting up breakpoints. Debug/Release x86/x64 is not what you want spend time figuring out especially when Visual Studio Community creates way to many subfolders. Nowadays I use g++ to compile, gdb to debug, valgrind+kcachegrind to profile, vscode to edit, and git for version control. There was a major period where I used no IDE and worked within Notepad++/Notepadpp or even nano, I did this as a beginner too, I don't think it was good or bad.

My learning style is weird, I've seldom been able to read a programming course or a programming book. The list of books I've read is fairly short. At lot of times, a quick tutorial will do. I can't focus on a rigid tutorial or course, but I am able to use just about any source available to solve a problem I have. I've been all over the web on YouTube, Reddit, GitHub, RFCs, StackExchange, wikis, documentation, or just browsing/using a project to get an understanding of how it works.

I don't really use ChatGPT/LLMs/AI to solve problems because they never could and still can't, I still can't trust them to critique my programs or give advice. They are not held to the pragmatic constraints of the real world. I'm sure they may be okay for a beginner, but you need to write for yourself and understand how to solve problems better than any AI agent.

In regards to my deep opinion I have no facts to back up, the field is in a strange place. You have 250-1000 candidates for single job positions. Software engineers are doomed to be stressed by deadlines, clients, end users, coworkers, MBA bosses, working for startups. There's more of a focus on shipping software rather than developing well written software. There's no passion unless you create it for yourself. Many people love programming in the beginning all the way up until they begin working in the field. I fear all of this because it doesn't really matter how much time I invest or what great projects I create, when in reality we're just mammals stressing ourselves out for no good reason.
